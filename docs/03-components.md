The existing 1.1.0 Python package is retained. Workspace product release/date are
null: this is an engineering baseline, not a new product release. Domain modules
from the concept are responsibilities inside the future monolith, not independently
deployed/versioned services. Split components only when real ownership/contracts
justify it; migrate paths and versions deliberately.

Deployment currently describes how Application runs; this dependency is not a
claim that the topology is complete. Specification and UI Prototype are reference
artifacts, not runtime dependencies. No component imports code from The OA or siblings.

Application and Deployment checks listed in manifests include syntax checks only
at baseline. Missing integration/browser/recovery evidence is recorded in
[current-state review](04-current-state.md) and [testing policy](operations/testing.md).
Changing a package, schema or producer contract requires checking its consumers;
versioning alone does not establish compatibility.

# Selective evidence-linked investigation reports

Date: 2026-11-09. Status: **selected H3 design; not implemented**.
Owner: evidence/product/UX. Depends on qualified H1 annotations and core export/
verifier/permissions. H2 search may assist selection but is not a report prerequisite.
Inspired by documented Hunchly note/report/selective-export workflow, not its format.

## Requirements

### REQ-RPT-001 Frozen explicit selection and narrative

A report shall select explicit capture IDs, annotation revisions, order, headings
and bounded investigator narrative. Preview pins exact corpus/member/revision/hash
snapshot before generation. A live collection/filter query is not the frozen report;
changes afterward require a new report revision, never silently add/remove findings.
No automatic inclusion of every note, capture, private search term or unselected case.

### REQ-RPT-002 Separate reference and original-evidence profiles

Define `workspace-report-reference/1` for narrative/selected derivative material and
citations without original bytes; label originals as referenced/not included and
do not claim independently verified original completeness. Define
`workspace-report-evidence/1` to additionally include explicitly selected complete
original evidence packages under verified inventories. Both profiles have their
own manifest/time/hash/omission rules and retain source capture profile identity.
A report is not a replacement capture receipt, database backup or public Publication.

### REQ-RPT-003 Exact citations and honest provenance

Every source-bearing quote/crop/report element shall identify capture/artifact
digest, annotation/derivation revision and actual provenance scope. Separate original
capture time, import time, annotation time and report generation time. Distinguish
verified byte match from user assertion/unknown foreign provenance; disclose fidelity
warnings. Preserve context links in-app and portable identifiers outside it. Neither
polished layout nor hashes/signatures are legal admissibility or truth guarantees.

### REQ-RPT-004 Reviewable disclosure without hidden metadata

Preview exactly included URLs, usernames/actor information, rationale/context,
note/quote/crop bodies and original files. Defaults exclude internal rationale,
unselected notes, cue/profile definitions, raw headers and unrelated audit history.
Original-evidence inclusion warns that those original packages can contain private
URLs/content; removing a label is not redacting source bytes. Explicitly choose
reference-only or keep private when original disclosure is unsuitable. No external
delivery/publication follows generation; C4 payload permissions do not expand.

### REQ-RPT-005 Bounded safe generation and verification

Use durable jobs and controlled templates with escaped content, no archived active
HTML or arbitrary resource fetching. Render derivative image references offline;
PDF is available only after the separate safe renderer is qualified and explicitly
selected. A requested required output failure cannot silently downgrade the profile.
Verify inventory, selected-original/derived hashes, generated byte hashes and
profile completeness before ready. Reject oversize reports rather than drop sections.

### REQ-RPT-006 Revision, retraction and recovery semantics

ReportRevision is immutable after snapshot/generation; edits create a new revision.
Reauthorize input/result/download before access. Retraction/purge/unavailable pinned
note/input blocks new generation until explicit revised selection, never swaps to
latest quote or silently omits it. Previously downloaded reports cannot be recalled.
Restore preserves snapshot identities and holds output/sending until deletion and
revocation ledgers are applied. Corrupt/missing bytes are unavailable, not rebuilt
from a current live page.

## Model and API

Report has UUID, collection reference, owner and latest revision; ReportRevision
stores ordered element descriptors, selected corpus/annotation snapshot, profile,
inclusion flags/disclosure preview digest, generated artifact keys/hashes, actor/
times and job state. ReportElement kinds: heading, narrative, verified_quote,
image_region, capture_reference. All source references are explicit; narrative is
user commentary. Brand/logo assets, if later supported, must be local approved
instance assets rather than arbitrary URL downloads.

POST `/api/v1/reports` or `/{id}/revisions` stages a bounded selection; POST
`/reports/{id}/revisions/{revision}/generate` requires snapshot/preview digest,
expected_revision and Idempotency-Key. GET preview/status/download is protected and
no-store. Input revision conflict is 409, unsupported profile/renderer 422, quota/
size/missing dependency is explicit. No public report URL exists in first H3.

Selected initial caps: 25 captures, 100 report elements, 1 MiB narrative/quote text
total, 16 MiB generated HTML and 512 MiB total package/spool; one rendering slot,
512 MiB worker memory and 120s generation deadline. Original evidence may make a
small selection exceed the package cap; reject or request an explicit smaller
selection. No automatic omission. Downloaded outputs follow private export expiry;
report snapshot/status persists, but expired bytes require authorized supported rebuild.

## Inventory and verification

Package: report.html, report.json (profile/snapshot/caveats), selected derivative
files, optional explicitly selected original packages, manifest.json, SHA256SUMS
and README.txt; optional required PDF only when selected. Manifest does not hash
itself; checksum file covers package files/manifests except itself, following the
established byte/path rules. Reference-only profile distinguishes package integrity
from absent-original verification. Independent verification reports what was actually
included and what remains a reference, never a universal "all evidence verified".

ADR-008/document 41 distinguishes ordinary annotation retraction from operator
removal: retracted pinned input blocks new generation, while an existing exact
historical output may remain with a visible warning unless removal/integrity/access
policy blocks it. Root removal fences block affected ready downloads immediately,
including embedded copies, before paged cleanup. Edits never silently change frozen
report selection. Document 40 applies purpose-specific eligibility per source/profile.

# Production export, safe PDF receipts and independent verification

Date: 2026-11-09. Status: **selected refinement; no PDF/export generated**.
Owner: evidence/rendering/security. Authority: ADR-010. Refines REQ-EVD-003/005/006/
008, REQ-SCP-003, REQ-SEC-007 and production ACC-12. V0 PDF remains optional unless
explicitly requested; native PDF-source acquisition remains a separate deferred feature.

## Production export inventory

workspace-export-production/1 contains exact accepted workspace-capture-production/1
files under `capture/`, plus `export.json`, `receipt.html`, `receipt.pdf`,
`manifest.json`, `SHA256SUMS` and `README.txt`. Existing capture/export self-hash,
canonical JSON/path/inventory rules remain authoritative. The complete export has
required PDF and WARC through the included original capture set; missing either
is failure, never an omitted optional field or a renamed V0 export.

Capture manifest stays immutable. Export manifest inventories every package file
except itself and SHA256SUMS; checksum file covers all package files except itself,
including both manifests. Whole ZIP digest/size is stored separately. Receipt lists
original capture manifest/artifact digests, not its own digest or a future ZIP hash;
there is no recursive PDF/manifest checksum dependency. Multiple exports can differ
in generation time/encoding while preserving identical original capture bytes.

Explicit editorial/actor inclusion still pins selected revisions and disclosure
preview; default excludes notes, user identity and internal request rationale.
WARC/MHTML/metadata can contain sensitive original content even if receipt labels
are hidden. Do not imply export option changes sanitize the original included files.
H3 reports and browser/native-transfer packages retain their own profiles/gates.

## Controlled receipt renderer

Use the existing WeasyPrint direction only after a pinned isolated renderer is
qualified. Input is a typed escaped ReceiptModel: profile/capture/artifact references,
approved display fields, capture versus export times, declared recording/fidelity
warnings, exact inventory/digests and verification instructions. No arbitrary HTML/
CSS/JS/template supplied by a page, annotation, uploaded case or administrator.

Build HTML/CSS from versioned packaged templates. Treat URLs/notes/titles as plain
bounded text; no source iframe, fetched favicon, remote stylesheet/font, user SVG,
attachment or active PDF action. Original screenshots may be represented only by
a separately validated bounded thumbnail with transform/hash and link-to-original
identity, never replacement bytes. Optional logo is a preapproved local instance
asset, not an arbitrary request URL.

Custom resource resolution accepts only job-manifest asset IDs for fixed fonts/
approved raster thumbnails/templates. Deny file/http/https/ftp/data and unresolved
paths even inside nested CSS/images. Renderer runs offline, non-root, without DB/
session/host secrets and with only selected read-only input/output namespaces.
A resource resolver is not the OS isolation/resource boundary; both are required.

## Resource and output contract

Selected initial receipt-only limits: 2 MiB generated HTML, 16 MiB PDF, 100 pages,
approved raster thumbnail <=2 million pixels/2 MiB, 512 MiB renderer memory and
60s renderer deadline. The parent export retains 120s total deadline/512 MiB package
cap and shared temporary/compute reservations. Image preparation, rendering,
verification and packaging all count against parent budgets, not hidden extra time.

Reject over-limit input/output or missing glyph/required-asset/render failure with
an actionable status; never silently drop pages/rows, shrink text beyond readable
layout or omit PDF. Deterministic fixture content/template/font options enable
stable review, but do not promise bit-identical PDFs across unsupported versions.
The actual generated bytes have their own hash and renderer/template/font identities.

Before ready, a separately bounded parser checks non-empty valid PDF structure,
page bounds and the selected no-attachments/no-active-action contract. Required
field/content fixture checks and page rendering QA catch unreadable/blank/truncated
layout; a `%PDF` prefix is insufficient. Test Unicode, long URLs/digests, RTL text,
escaping, oversized notes and page breaks without changing original source strings.
Receipt-only PDF is not automatically PDF/A, PDF/UA, signed or legally authenticated.

## Failure and compatibility

V0 include_pdf=false creates only its declared V0 inventory; disabled PDF is shown
as unavailable. V0 include_pdf=true and production export both require successful
renderer/output checks. Status transitions remain queued/rendering/verifying/ready
or explicit failed/cancelled/expired; a caught renderer exception cannot become ready.
Partial renderer bytes stay private temporary diagnostics and follow bounded cleanup.

Existing V0/browser/foreign evidence cannot be upgraded by generating a production
receipt. The export service resolves exact supported profile, current permission/
dependency fences and immutable input identity before each phase/ready/download.
Expire output after the existing 24h spool lifetime; rebuilding is authorized work,
not changing an old completed output's digest or acquiring today's live page.

## Independent verifier contract

Verifier runs on an explicit local package with no Workspace session, network or
source fetch. Distinguish (a) supported profile/declared complete inventory,
(b) member/path/size/whole-file hashes, (c) WARC/PDF structural/content constraints,
(d) recorded provenance/scope claims and (e) optional replay QA evidence. Byte
verification is not proof of source truth, capture authorship or trusted time.

Stream bounded ZIP parsing: reject absolute/dot/backslash/case-colliding/duplicate
names, links, undeclared members, zip bombs and missing required inventory. Initial
production package cap 512 MiB stored and 768 MiB decoded aggregate, 1,000 ZIP
members; WARC's own inner decode/record limits are additional and shared with the
same finite process/temp budget. Compression declarations do not replace counting
actual decoded bytes. No extracted member can overwrite another or an external file.

Verification output is structured status/code/profile/checked-item counts and safe
failure location. An empty checksum file or partially checked package cannot pass.
Unsupported version is unsupported, not corrupt or verified. Independent commands
and tool/source identities are EWP-74/76 deliverables, not installed commands here.
Test tamper, truncation, missing/extra members, declared-inventory mismatch and real
interoperability outside the source deployment before ACC-12 production qualification.

Nested decoding counters are cumulative across package and WARC layers; count real
bytes, not just declared ZIP sizes. The aggregate decode cap is a work limit, not
permission to retain 768 MiB of extracted files. Stream bounded buffers/member
processing, charge actual physical snapshots/temp once under the shared 1 GiB pool,
and fail when the complete operation cannot fit. PDF metadata is fixed/allowlisted;
no host path, local username, hidden attachment or unexpected source action is copied
into metadata merely because a renderer supports it.

H3 report PDF, native PDF-source parsing and any archival/accessibility PDF
conformance are distinct adapters/gates. ReceiptModel qualification alone cannot
turn those features on or substitute receipt-specific caps/templates for ReportModel.
